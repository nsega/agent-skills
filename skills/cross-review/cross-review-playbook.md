# Two-agent cross-review playbook (v2)

**Setup:** Main = Claude Code + Opus 4.8 (reviewer #1 + synthesis + decisions/patch) / Sub = GLM-5.2 via OpenCode Zen (independent reviewer #2, with a dissent lens layered on)

**Core idea:** fixing the **inputs, roles, outputs, and dispositions** beats adding more models. The value is in the two reviewers' **disagreements**, so never average them away.

> `rubric.md` is the source of truth for severity and category, `SKILL.md` is the execution flow, and this document is the method. Checklists are not restated here, to avoid maintaining them twice.

---

## A. Fix the inputs

### 1. Build the review packet first (generated by Claude Code)
`gather_artifact.sh` fills the mechanical fields (changed files, diff/doc, test results). Claude fills the author fields before the packet goes to the reviewers.

```
- Background
- Purpose
- Non-goals                  <- most important. Prevents out-of-scope findings
- Key design decisions
- Known worries              <- most important. Aims the review
- Changed files / diff or commit hash (PR) / doc v1 (design)
- Test results
- What to review
```

**Two levels, full and minimal** (see G). Even `minimal` keeps **purpose, non-goals, diff, and test results**; the packet itself is never skipped.

---

## B. Roles and ordering (two-agent version)

### 2. The first review is independent and blind, and the scope of that independence matters
Showing one reviewer's findings to the other first pulls it along and kills the diversity.

```
Claude Code : produce the artifact -> package it
GLM-5.2     : independent external review (blind)
Claude Code : author-aware self-review (own findings to disk first)
              -- no reading GLM's output up to this point --
Claude Code : synthesis and disposition -> (after fixes) delta-review (see E)
```

**Claude as reviewer #1 is not a fully independent review.** It knows the authoring intent, so a self-justification bias remains. Countermeasures:

- The main lever is **subagent isolation**: hand Claude's review to a fresh context or subagent that does not carry the authoring intent.
- If you discount Claude's view, **limit that to design and architecture conflicts**. On correctness conflicts the author's knowledge is an asset, so do not discount it across the board.

### 3. Do not stack roles, but do not hard-partition them either
There is only one sub-reviewer, so the topics cannot be split in two:

- **GLM-5.2**: full review plus a **dissent, alternative-design, and hidden-assumption** lens (where a different lab pays off most). Reviewer #2 runs as N independent passes (default 3) unioned by (location, issue text); a finding's `pass_count` is agreement across passes, a ranking signal only, never a gate (real findings rarely recur, so singletons are kept).
- **Claude Code**: full review (reviewer #1) plus synthesis, trade-off judgment, and the final patch.

Do not restrict a reviewer to "look at security only." Weight the primary focus, but **always require findings outside that area too**, so nothing falls through the gaps or gets quietly dropped.

## C. Fix the outputs

### 4. Fix the finding format (conforms to `findings.schema.json`)

```
ID:           G-001 / C-001 (reviewer prefix; Claude renumbers to F-### at synthesis)
Severity:     critical / high / medium / low
Category:     see the enum in rubric.md / the schema
Location:     file:line (diff) / section (design)
Issue:
Evidence:     the basis (diff line, relevant spec, observed behavior); guards against hallucinated reviews
Failure case: when it actually bites (input, ordering, load)
Suggested fix:
Confidence:   high / medium / low
Recommendation: must_fix / should_fix / defer / nit (your call on your own
              finding; severity is impact, this is action. No "reject": you do
              not reject what you just raised, only the synthesizer does)
Speculative:  yes / no
```

**Evidence is required for critical/high and for correctness/security**, and critical/high also require a failure case (the schema enforces this). Low-severity findings outside correctness/security are exempt; note that a `nit` **recommendation** is not an exemption, since the schema keys only on severity and category.

### 5. Discipline prompt (shared by both reviewers)
```
Do not summarize first.
Start with findings ordered by severity.
Only include issues affecting correctness, security, maintainability, or operability.
Avoid style-only comments unless they create real maintenance risk.
```

### 6. Confidence is for ordering, not for cutting
AI confidence is poorly calibrated. Work in `high severity x high confidence` order, but **never drop low confidence x high severity: it always goes to a human** (the case where a model hedges on a genuine blocker). Mark speculation explicitly with `Speculative: yes`.

---

## D. Decide dispositions (where the quality is)

### 7. Isolate conflicts, but do not send them all to a human
A spot where the two reviewers rule opposite ways is a stronger signal than a single-reviewer finding. **Human escalation is conditional:**

Run `check_disagreements.sh` on the two findings files before reasoning about any of this. The synthesizer is one of the disputants, so "did anyone disagree with me" is the last question it should answer from memory. The checker matches on location only, so it is the floor: differently-framed descriptions of one issue still need the clustering scan in section 8.

```
To the human:
- EITHER reviewer rated it high or above, and the two `recommendation` values
  differ (a missing recommendation counts as differing: fail toward escalation)
- touches security / data loss / migration / public API
- Claude is about to disposition `reject` on a finding the other reviewer
  recommended `must_fix`
- Claude is about to disposition `reject` / `defer` on a finding CLAUDE itself
  recommended `must_fix` before seeing GLM's (no second reviewer catches this one)
- low confidence but high severity
- Claude is downgrading a finding GLM rated high or above to defer / reject
Other, lower-risk conflicts:
- Claude makes a provisional call and just notes "conflict / provisional disposition" in the summary
```

**Claude is both a disputant and the chair**, so three additional rules bind it:

- **When in doubt, fall toward escalating.** One extra line costs less than a suppressed blocker.
- **Do not self-resolve design/architecture conflicts in your own favor.** Author knowledge is grounds only in **correctness** conflicts. When author knowledge is your only ground on a design conflict, there are two options: GLM's reading stands, or it goes to the human. Design conflicts you can settle on grounds visible in the artifact still follow the normal escalation bar.
  **The category is the loophole:** Claude assigns it at synthesis, so for a GLM-raised finding use GLM's original category, and when it is arguable whether a conflict is correctness or design, treat it as design.
- **Always record dropped GLM findings.** Even below the escalation bar, they belong under "Not adopted" with a reason ("not adopted" means it never received an F-ID; a rejected finding that did get one goes under Disposition instead). Dropping them silently is the exact failure this topology exists to prevent. In lite, one grouped line is enough; itemized reasons are required in full.

### 8. Disposition and the finding ID lifecycle
At synthesis, Claude assigns each finding a canonical **F-###** and classifies it.

```
F-001  high / correctness   -> must fix
F-002  medium / maintainab. -> defer
F-003  high / design        -> escalate (conflict)
```

```
must fix / should fix / defer / reject
```
`reject` requires a reason. Example: `Reject(F-007): correct, but a non-goal for this PR. Changing the existing constraint is needed, so it becomes a separate issue.`
This is what turns a majority vote into a design decision.

## E. Fixes and re-review (two-agent version)

### 9. Delta-review: the fix diff only, with the IDs it should resolve
A full re-review is unnecessary. What matters after a fix is **the correctness of the diff**, not the whole design again.

```
default             : Claude self-check (fix diff against the must-fix F-IDs)
high risk           : GLM delta-review ... pass the fix diff plus "the must-fix F-IDs
                      to verify", and have it check only two things: (a) is each
                      finding resolved, (b) did the fix introduce a regression
major design change : have a fresh-session GLM review the fix diff (restores
                      independence)
```

High risk = security / data loss / migration / public API. GLM never re-reads the whole artifact, so the cost stays low.

---

## F. Hand off to the human

### 10. A summary as decision material (tracked by F-ID)
```
- Adopted (F-001 fixed, F-004 fixed ...)
- Rejected (F-007 rejected, with reason)
- Dropped GLM findings (Not adopted: G-00x, with reason)
- Escalated (F-003 escalated to human)
- What was changed
- Residual risk
- Test results / delta-review results
- Points for the human to look at (including the conflicts)
```

## G. Tier by stakes (packet + process scaling)

| | lite (daily PR) | full (important design / high-risk PR) |
|---|---|---|
| Packet (A) | **minimal** (purpose, non-goals, diff, test results) | full |
| Independent review (B) | GLM 3 passes (or `1` for cheap lite) + Claude synthesis | both fully blind (Claude via subagent if possible) |
| Disposition (D) | must fix only | all classes + reject reasons + conflict isolation |
| Re-review (E) | Claude self-check | delta-review (GLM when high risk, fresh session when major) |
| Human summary (F) | brief (dropped GLM findings as one grouped line) | full (F-ID tracked, itemized "Not adopted" reasons) |
| **GLM effort** | **Max** (always) | **Max** (always) |
| **Claude deep pass** | medium | high / max |

`small_model` (title generation and similar) stays minimal at all times. Spend high effort only on the deep passes.

---

## Recommended flow (full)

```
package it (Claude fills the author fields)
-> save Claude's author-aware self-review first (subagent if possible)
-> GLM independent review (blind)
-> synthesize findings under F-IDs
-> isolate high-risk conflicts (-> human)
-> disposition (must / should / defer / reject)
-> fix the must-fix items only
-> Claude self-check
-> GLM delta-review for high risk only (security / public API / data migration)
-> summary for the human (residual risk, conflicts, F-ID tracking)
```

## Feedback folded into v2

1. Added **Evidence + Failure case** to findings (required for critical/high and correctness/security; low-severity findings outside those categories are exempt). Enforced by the schema.
2. Introduced **finding IDs** (reviewer prefixes G-/C-, renumbered to F-### at synthesis). Fixes, re-review, and the summary are tracked by ID.
3. **A minimal packet is required even in lite** (dropped the option of omitting it entirely).
4. **Made conflict escalation conditional** (stopped sending everything to a human; the conditions live in section 7 and are not restated here, so they cannot drift).
5. **Delta-review** (fix diff + must-fix IDs only, GLM when high risk, fresh session when major).
6. **Scoped the independence discount** (discount Claude's self-review only on design conflicts, not on correctness; the main lever is subagent isolation).
7. Unified severity to **critical/high/medium/low** (matching the schema, rubric, and SKILL.md).
