## 1. Overview

This repository is a personal, git-managed collection of [Agent Skills](https://docs.claude.com/en/docs/claude-code/skills) for Claude Code (and, opt-in, Codex). Its design philosophy is **symlink, don't copy**: each skill folder is per-folder symlinked from the repo into one or more skills directories, so editing a skill in the repo takes effect immediately, with no install step to re-run. [README.md:6-8](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md#L6-L8)

The system has three moving parts: a **Makefile** that defines sources and targets, a **linking engine** (`scripts/link.sh`) that creates and audits the symlinks under strict safety rules, and the **skills themselves** (`skills/<name>/SKILL.md`). Two sources feed every target: this repo's own `skills/` directory (all skills), and an optional curated subset of a local [anthropics/skills](https://github.com/anthropics/skills) clone. [README.md:24-31](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md#L24-L31) Beyond installing, the engine also audits each target directory for **drift**: entries that no configured source owns, and owned links whose skill has vanished from its source. [README.md:85-89](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md#L85-L89)

## 2. Linking engine (link.sh)

`scripts/link.sh` is a single bash script with a four-command contract (`install`, `uninstall`, `status`, `unmanaged`) dispatched at the bottom of the file. [scripts/link.sh:187-193](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L187-L193) It runs under `set -euo pipefail` [scripts/link.sh:34](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L34) and takes `<cmd> <target_dir> <src_dir> [skill...]`, where the trailing arguments are a skill whitelist for `install`/`status`, but **additional source dirs** for `unmanaged`. [scripts/link.sh:6-12](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L6-L12) [scripts/link.sh:23-27](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L23-L27)

A non-existent source directory is a **warn-and-skip no-op** (exit 0), which is what lets the Makefile list optional sources, like the upstream clone, that may not exist on every machine. For `unmanaged` the handling is command-aware: a missing source is silently skipped (it owns nothing) and the check still runs against the remaining sources instead of aborting. [scripts/link.sh:47-57](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L47-L57)

The ownership test at the heart of every destructive decision is `points_into_src()`: a symlink is only ever touched if its target resolves inside the given source directory. [scripts/link.sh:60-65](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L60-L65)

### 2.1 Skill selection

`selected_skills()` emits the skill names to act on: the explicit whitelist (each name validated to have a `SKILL.md` under the source, with a warning for misses), or, when no whitelist is given, every directory in the source that contains a `SKILL.md`. [scripts/link.sh:67-86](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L67-L86) The whitelist applies to `install`/`status` only; `uninstall` always acts on all links pointing into the source. [scripts/link.sh:9-12](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L9-L12)

### 2.2 Install states

`do_install()` classifies each skill into one of five states, and only two of them write to disk: [scripts/link.sh:88-112](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L88-L112)

| State | Condition | Action |
|---|---|---|
| `ok` | symlink already points at the source skill | none (idempotent) [scripts/link.sh:97-98](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L97-L98) |
| `fixed` | stale symlink that still points into the source repo | repointed with `ln -sfn` [scripts/link.sh:99-101](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L99-L101) |
| `warn` (foreign) | symlink pointing somewhere else | skipped, never clobbered [scripts/link.sh:102-103](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L102-L103) |
| `warn` (non-symlink) | a real file/dir occupies the name | skipped, never clobbered [scripts/link.sh:105-106](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L105-L106) |
| `linked` | nothing there | symlink created [scripts/link.sh:107-109](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L107-L109) |

### 2.3 Uninstall and status

`do_uninstall()` walks the target directory and removes **only** symlinks whose target passes `points_into_src()`; foreign links and real files are untouched, so uninstalling one source repo never disturbs another's links. [scripts/link.sh:114-125](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L114-L125)

`do_status()` is read-only and reports `ok` / `wrong` / `blocked` (non-symlink in the way) / `missing` per skill. [scripts/link.sh:127-146](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L127-L146)

These behaviors are surfaced to users as the README's "Safety guarantees" list. [README.md:75-89](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md#L75-L89)

### 2.4 Drift reporting: unmanaged and dangling

`do_unmanaged()` is the audit complement to `status`. Where `status` walks the **source** (skills that should be linked), `unmanaged` walks the **target** and reports what none of the given sources can account for. It accepts multiple source dirs in one invocation (`unmanaged <target_dir> <src_dir> [src_dir...]`), because an entry owned by one source must not be flagged while checking another. [scripts/link.sh:23-27](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L23-L27) [scripts/link.sh:155-185](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L155-L185)

An entry is *owned* when it is a symlink whose raw `readlink` target sits inside any source dir; `link.sh` always creates absolute links, so a raw prefix match suffices (the same rule as `points_into_src()`). [scripts/link.sh:148-154](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L148-L154) Each target entry then falls into one of three reported/silent classes: [scripts/link.sh:163-184](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L163-L184)

| Report | Meaning |
|---|---|
| `unmanaged <name> -> <target>` | foreign symlink; no source owns it [scripts/link.sh:176-177](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L176-L177) |
| `unmanaged <name> (not a symlink)` | plain file/dir sitting in the target (e.g. a hand-made skill not in git) [scripts/link.sh:181-183](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L181-L183) |
| `dangling <name> -> <target>` | owned link whose skill was renamed/deleted in the source; invisible to `status`, which never visits names absent from the source [scripts/link.sh:178-179](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L178-L179) |

Healthy owned links stay silent (name-preserving drift is `status`'s job), missing source dirs own nothing and are skipped, and the whole command is read-only. [scripts/link.sh:148-162](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L148-L162)

**Sources:** [scripts/link.sh](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh), [README.md](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md)

## 3. Make orchestration

The Makefile is the entrypoint; it owns all configuration defaults and loops, while delegating filesystem work to `link.sh` ([Makefile:30](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L30)).

| Variable | Default | Role |
|---|---|---|
| `CLAUDE_SKILLS_DIRS` | `~/.claude/skills ~/.claude-work/skills` | one target per Claude Code identity [Makefile:23](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L23) |
| `CODEX_SKILLS_DIR` | `~/.codex/skills` | opt-in Codex target [Makefile:24](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L24) |
| `REPO_SRC` | `$(abspath skills)` | this repo's own skills (always linked) [Makefile:26](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L26) |
| `UPSTREAM_REPO` | a local `anthropics/skills` clone | optional second source [Makefile:27](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L27) |
| `UPSTREAM_SKILLS` | `mcp-builder skill-creator` | curated upstream subset [Makefile:28](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L28) |

`install`, `uninstall`, and `status` each iterate over every dir in `CLAUDE_SKILLS_DIRS`, invoking `link.sh` once for the repo source and once for the upstream subset. [Makefile:46-66](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L46-L66) The `status` target additionally runs one `unmanaged` sweep per target dir, passing **both** sources in a single call so cross-source ownership is judged correctly. [Makefile:65](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L65) Note the asymmetry: `uninstall` passes no skill whitelist, because uninstall removes everything pointing into the given source regardless of the curated list. [Makefile:53-58](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L53-L58)

The Codex targets (`install-codex` / `uninstall-codex` / `status-codex`) are separate, single-target, and link **this repo's skills only**; the upstream subset is not mirrored to Codex. `status-codex` gets the same `unmanaged` sweep against the repo source. [Makefile:68-77](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L68-L77)

All variables are environment-overridable for testing (`CLAUDE_SKILLS_DIRS="/tmp/a /tmp/b" make install`). [README.md:67-73](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md#L67-L73)

## 5. Scaffolding new skills

`make new name=<skill-name>` delegates to `scripts/new.sh` [Makefile:80-81](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L80-L81), which:

1. Validates the name as kebab-case (`a-z 0-9 -`, no leading/trailing hyphen). [scripts/new.sh:19-24](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/new.sh#L19-L24)
2. Refuses to overwrite an existing `skills/<name>/`. [scripts/new.sh:31-34](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/new.sh#L31-L34)

The template is a minimal frontmatter scaffold (`name:` + `description:`) plus "When to use" / "What it does" section stubs. [templates/SKILL.md:1-14](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/templates/SKILL.md#L1-L14)

Per-skill scratch directories (`*-workspace/`) are gitignored so iteration debris never becomes a "skill". [.gitignore:7-8](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/.gitignore#L7-L8)

## 6. Glossary

- **Skill**: a folder containing a `SKILL.md` with `name:`/`description:` frontmatter; the unit that gets symlinked and that Claude Code discovers. [templates/SKILL.md:1-4](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/templates/SKILL.md#L1-L4)
- **Per-folder symlink**: one symlink per skill folder (never a single top-level link), so sources can mix and individual skills can be blocked or skipped independently. [README.md:77](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/README.md#L77)
- **Identity**: one Claude Code config dir (e.g. `~/.claude`, `~/.claude-work`), each with its own `skills/` target; `CLAUDE_SKILLS_DIRS` holds one entry per identity. [Makefile:13-15](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L13-L15)
- **Upstream subset**: the curated list of skills linked from a local `anthropics/skills` clone rather than copied into this repo. [Makefile:6-11](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/Makefile#L6-L11)
- **Foreign symlink**: a link in a target dir that does not point into the current source repo; never modified or removed, and reported by `unmanaged`. - **Whitelist**: optional trailing skill names passed to `link.sh`, restricting `install`/`status` to a subset of the source. [scripts/link.sh:9-12](https://github.com/nsega/agent-skills/blob/67e11e2a952ced5d23c88de0a6555abd039659cf/scripts/link.sh#L9-L12)
